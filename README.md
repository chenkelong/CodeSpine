# 码脊 CodeSpine

> CT-scan your code changes —— 确定性提取 diff 骨架，AI 完成语义分析，渲染可循行号的评审视图。

## 快速开始

```sh
npm i -g git+ssh://git@github.com/chenkelong/CodeSpine.git
cd 你的项目
codespine ct                  # ① 断层扫描 → .codespine/<分支>/spine-raw.json
# ② AI 按 prompts/ANALYSIS.md 把 raw 转成 spine.json（skill 见 platforms/）
codespine audit --raw         # ③ 验收：行号回读，骨架层零容错
codespine render              # ④ 评审视图 → .codespine/<分支>/review.html
```

所有产物归档在 `.codespine/<分支名>/` 下，建议将该目录加入 `.gitignore`（ct 会自动询问）。

## 命令

| 命令 | 说明 | 默认行为 |
|---|---|---|
| `codespine ct` | diff 断层扫描 | 智能默认基准（origin/master → origin/main → master → main），产出含内容快照 |
| `codespine audit` | 验收 spine.json | 默认读当前分支目录，`--raw` 自动找同目录快照 |
| `codespine render` | 渲染 HTML | 内置模板（AI 不可改），同数据输出 MD5 一致 |

选项：`--base` / `--head` / `-o` / `--no-content` / `-C` / `-y`

## 两种使用形态

| 形态 | 组成 | 适合 |
|---|---|---|
| agent 模式 | codespine 包 + skill 装进你的 AI（zcode/codex） | 重度 AI 用户 |
| 独立模式（规划中） | codespine + 配置 API key（DeepSeek 等） | CI / 不用 agent 的同学 |

## 五视图评审界面

### 变更概览（默认首页）
变更说明 + 核心变更点（带阅读序号，可跳转链路）+ 基线信息 + 评审关注点 + 证据来源图例

### 影响链路
入口卡片行（灰色=入口未变更）+ 纵向调用链（精简/完整切换）+ **右栏双卡详情**：
- 上卡 = 入口信息（URL 复制 / 入参 / 出口）
- 下卡 = 类或块详情（路径/FQCN/检索串复制 + 关键代码 + 调用路径 + 逻辑块定位）

### 代码差异
- **左右分栏**：左侧文件树（A/M 状态 + 文件名 + 增删统计），右侧 diff 内容
- **函数级组织**：按方法分组，每块显示**完整方法体**（从签名到 return + 闭括号）
- 方法块标题：`文件名#函数名()  L起始-结束  N 处变更`
- diff 行着色：绿底 `+`（新增）/ 红底 `−`（删除）/ 上下文灰显
- 未变更区域折叠：`⋯ N 行未变更 ⋯`，**方法体最后 5 行永不折叠**
- 属性/导入变更独立分组（📦）

### 独立变更
非链路变更独立卡片（文档/配置/枚举等）+ 全量文件索引（每个文件在哪条链的什么位置，无遗漏）

### 验证情况
**AI 风险分析**（通俗版描述 + 生活类比）+ 交互式确认 + 分析质量 + 尚未覆盖范围

每项风险包含：
- 描述（用生活场景类比，外行也能懂）
- 证据（代码行号引用）
- 建议（对话式，"问一下作者" / "确认一下"）
- 三个操作按钮：✓ 确认无风险 / ⚠ 有风险 / 跳过
- 响应存储在 localStorage，刷新页面自动恢复

## 证据分级

| 标识 | 含义 |
|---|---|
| 🟢 源码事实 | 可直接由代码或配置确认 |
| 🟡 分析推断 | 基于上下文得出的判断 |
| 🔴 待确认 | 需要作者或评审者确认 |
| 🔵 已验证 | 有执行结果及证据支持 |

## 分层哲学

```
命令层（确定性）: ct 提取骨架 · audit 守门 · render 渲染
Skill 层（AI）  : 语义分析——链路组织/逻辑块命名/风险识别（prompts/ANALYSIS.md）
契约            : spine-raw.json → spine.json（SCHEMA.md）
红线            : 骨架层是事实（行号/调用关系零容错）；概率只住在语义层
```

## 核心设计决策

| 决策 | 理由 |
|---|---|
| 调用图确定性生成，不允许 AI 凭印象 | 漏一跳评审者就断线（踩过两次坑） |
| 方法检测只匹配 public/private/protected + `{` | 宽松匹配会把 `xxx.add()` 语句碎片化方法体 |
| 块排序 = 调用链行号字典序（逻辑推进序） | 评审按代码执行顺序走，不按文件物理行序 |
| 代码差异显示完整方法体 | 孤立的 diff 行缺乏上下文，无法判断变更影响 |
| 样式全部内置模板，AI 不可改 | 换任何模型跑 skill，界面永远一样（MD5 验证一致） |
| "已省略"替代"未变更" | 摘录跳过 ≠ 代码没变，不能误导 |
| 风险描述用通俗类比 | 评审者可能不了解上下文，专业术语增加认知负担 |
| 卡片间距 > 12px，行高 ≥ 1.8 | 密集排版让人看不下去 |
