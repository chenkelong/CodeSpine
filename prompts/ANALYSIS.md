# 码脊 CodeSpine —— AI 语义分析规则（ANALYSIS）

> 你的角色：把 `spine-raw.json`（确定性 diff 骨架）转化为 `spine.json`（评审视图数据）。
> **铁律：骨架层是事实。行号、调用关系、方法边界只能引用 raw 中已有内容，禁止编造；不确定就降低置信度或标 refOnly。**

## 输入 / 输出

- 输入：`codespine ct` 产出的 `.codespine/<分支>/spine-raw.json`（文件/hunk/行级 diff + 新侧内容快照）
- 输出：符合 `SCHEMA.md` 的 `spine.json`，随后必须通过 `codespine audit --raw`

## 分析七步

1. **diff 解读**：每个文件判断变更类型（新增类/修改类/字段配置类/文档），统计方法级变更（签名行在 diff 内 = 新增方法，否则 = 修改）。
2. **入口溯源**：从每个变更类**向上遍历调用方，直至 HTTP 入口（Controller/路由），最深允许 7 层**。每一跳必须逐跳验证（在 raw 内容快照里确认调用点存在），**禁止凭"业务上应该相关"挂链**。找不到入口的进独立变更。
3. **链路组织**：入口 → 未变更中间层（薄委托/编排层）→ 变更类。未变更中间层保留为节点，标注 `callLines`（≤3 行关键调用，含行号与下一跳）。
4. **逻辑块切分**：每个变更方法拆 3~6 个语义块；块名 = **动宾短语 ≤8 字**（如"保存前重核权益"）；每块带 `range`（行区间，来自 raw hunk）、`desc`（一句话）、`via`（向上调用路径，每跳含调用行号）、`snippet`（3~5 行关键代码，含真实缩进，从 raw content 回读）。大方法（>50 行或 >6 块）允许一层 phases 分组。
5. **入参对象**：入口的参数 DTO 有字段级变更时，建 `params.objects`（嵌套位置 + 字段 + `+/−/~` 类型 + 说明）。入参对象卡独立于链路展示，点击可看字段详情。
6. **覆盖率闭包**：`变更文件全集 − 已挂链文件 = 差集`，写入 `orphans`（含原因分类：非调用引用/文档/无上游入口等）与 `coverage.inventory`（全量文件索引：每个文件在哪条链的什么位置——**任何变更不允许静默丢失**）。
7. **自检**：产出后逐块核对——via 每跳的行号回读内容快照、snippet 行号与文本一致、in 标注的方法确实包含 range。**行号必须机器回读，不靠记忆。**

## 排序与去重规则

- **块排序 = 逻辑推进序**：排序键 = `[via 各跳调用行号..., 自身起始行]` 字典序（深度优先执行顺序）。被调函数的块排在其被调用点之后，不是文件物理行序。
- **枢纽去重**：同一类在一条链中第二次出现 → `refOnly: true`（引用芯片，首次才展开）。
- **跨链复用**：编辑链复用创建链的类 → refOnly + badge "复用创建链"。

## 方法检测规则（关键修正）

**只匹配真正的 Java 方法声明**，避免把 `xxx.add()`、`this.saveBatch()` 等语句误判为方法：

- 必须以 `public`、`private`、`protected` 开头
- 必须包含 `(`（有参数列表）
- 必须以 `{` 结尾（或下一行是 `{`）
- 排除 `class`、`interface`、`enum` 声明
- 方法边界：从声明行往下，找与声明行相同缩进的 `}` 作为结束

**错误示例**（这些不是方法声明，不要检测为方法）：
```
filteredTaskIds.add(toTaskId);          // 语句，非声明
this.saveBatch(migratedValues);          // 语句
toValue.setId(IdGen.next());             // 语句
```

## 术语规范

| 统一使用 | 禁止使用 | 原因 |
|---|---|---|
| 变更点 | 病灶 | 评审是工程活动，不是治病 |
| 精简链路 / 完整链路 | 只看脊痕 / 完整码脊 | 直白易懂 |
| 独立变更 | 未挂链 | 独立是一种正常状态，不是缺失 |
| 已省略 N 行 | 未变更 N 行 | 摘录跳过 ≠ 代码没变 |
| 属性与导入 | — | import/字段/常量的分类名 |

## 证据分级标识

每条语义判断标注来源，模板会渲染为彩色徽章：

| 标识 | 含义 | 使用场景 |
|---|---|---|
| `fact` 源码事实 | 可直接由代码或配置确认 | 行号、方法签名、调用关系 |
| `infer` 分析推断 | 基于上下文得出的判断 | 影响范围、业务意图
| `unconf` 待确认 | 需要作者或评审者确认 | 调用链路需人工核实 |
| `veri` 已验证 | 有执行结果及证据支持 | 行号回读验收通过 |

同时展示"未分析、无法解析、缺少证据"等状态，**避免页面完整被理解为分析完整**。

## 表达规范

- 所有方法引用带归属前缀（`Support.isSpecialField`，避免同名混淆）
- 未变更节点在"精简链路"模式下要么是 ≤3 行调用行的轻量卡，要么是折叠药丸
- 说明文案：块 desc 一句话；入口/出口条带业务语义；`generatedBy` 注明分析方式
- 方法块标题格式：`文件名#函数名()`（如 `CheckModifyModuleServiceImpl#modifyProcess()`）
- 参数变更标注：节点/块上有 `paramChanged: true` + `pcNote`（说明签名变化内容）

## 禁止事项

- 禁止编造行号 / 虚构调用边 / 语义挂链（"看起来相关"不算调用）
- 禁止把删除的配置文件混进链路节点
- 禁止在骨架层使用"大概/可能"——不确定属于语义层，用置信度表达
- 禁止方法检测时把语句（`xxx.add()`）误判为方法声明
- 禁止把技术评估文档（.md）混入代码链路节点——归入独立变更
